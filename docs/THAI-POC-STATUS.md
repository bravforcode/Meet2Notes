# ผลทดลอง Meet2Notes ภาษาไทย–อังกฤษ

ข้อมูล ณ 17 พฤศจิกายน 2026 · PoC บน Windows

## เสียงจำลอง

สร้างบทพูดสมมติสองประโยคด้วย Microsoft Pattara บนเครื่องและ Google Translate TTS (ส่งเฉพาะข้อความสมมติไปภายนอก) ป้อนเป็นไมค์จำลองและเสียงปลายทางจำลองผ่าน AudioMixer ของ Meet2Notes โดยไม่เปิดไมค์ในชุดทดลองนี้ สัญญาณแต่ละฝั่งในช่วงเวลาของตัวเองมี correlation กับต้นทางมากกว่า 0.999999 ยังไม่ได้ทดสอบเสียงพูดซ้อนหรืออุปกรณ์จริง

| OpenAI Whisper CPU FP32 | CER รวมเมื่อแยกสองช่วง | CER ไฟล์สองช่วงรวม |
| --- | ---: | ---: |
| tiny | 61.36% (27/44) | 54.55% (24/44) |
| base | 56.82% (25/44) | 79.55% (35/44) |

CER คือระยะห่างของอักขระหารด้วยจำนวนอักขระอ้างอิง หลังปรับ Unicode และตัดช่องว่าง/เครื่องหมายวรรคตอน ไม่ใช่เปอร์เซ็นต์ความถูกต้องของความหมาย ไฟล์รวม base ตกหล่นช่วงที่สอง คำ report และ email และข้อความวัน/เวลาตรงตัวไม่ครบในทั้งสองรุ่น แต่การตรวจตรงตัวนับคำทับศัพท์หรือรูปสะกดที่มีความหมายเดียวกันเป็นข้อผิดพลาด ต้นฉบับอ้างอิงคือข้อความที่สั่ง TTS และยังไม่มีคนฟังตรวจการออกเสียง ดูวิธีและแฮชใน [RESULTS.md](../poc_benchmark/RESULTS.md) และ [README.md](../poc_benchmark/README.md)

## บันทึกและความปลอดภัย

เมื่อเลือก Detailed Thai-English Meeting และไม่มีโมเดลสรุปในเครื่องพร้อมใช้ ระบบสร้าง transcript พร้อมเวลาเป็นบันทึกสำรอง โดยระบุว่าไม่ใช่สรุป AI และไม่เดามติ งาน ผู้รับผิดชอบ หรือกำหนดส่ง ระบบคัดบรรทัดต้นฉบับที่พบคำค้นเกี่ยวกับเวลาและการติดตามงานให้ตรวจเพิ่มเติมไม่เกิน 30 บรรทัด และแสดง transcript ฉบับเต็มเสมอ การจับคำอาจให้ผลที่ไม่เกี่ยวข้องหรือตกหล่นข้อความสำคัญ และไม่ยืนยันว่าข้อความนั้นเป็นงานหรือกำหนดส่ง หากมีสรุปจากโมเดล ระบบตรวจ timestamp ในรูปแบบที่กำหนดเทียบกับ transcript แต่ timestamp ที่ตรงไม่ได้ยืนยันความถูกต้องของเนื้อหา

ทดสอบ API ด้วยฐานข้อมูลชั่วคราวและ transcript จำลองที่ใส่ลงฐานข้อมูลโดยตรง ไม่ใช่ output ASR; โหมดสำรองไม่ใช่ AI summarization และยังไม่ได้ทดสอบ LLM จริง ระหว่างตรวจ UI ครั้งแรก หน้าต่างสร้างประชุมเดิมเรียกวัดระดับไมค์อัตโนมัติทั้งที่ผู้ใช้ขอเสียงจำลอง ผู้ทดสอบปิดหน้าต่างทันที; log ที่เห็นแสดงการวัดระดับ แต่ไม่พบการเริ่มบันทึกไฟล์เสียง หลังแก้ไขปิดการวัดอัตโนมัติแล้ว และปุ่ม Test audio levels จะเปิด input เมื่อผู้ใช้กดเอง; API เปลี่ยนเป็น POST และตรวจ Origin และ header ก่อนเปิดอุปกรณ์ ซึ่งไม่ป้องกันโปรเซสในเครื่องที่จงใจปลอมคำขอ

ทดลองเรียก OpenAI `gpt-4o-mini` ผ่าน summary adapter หนึ่งคำขอ โดยส่งเฉพาะ transcript สมมติและจำกัดผลลัพธ์ 256 tokens: ได้ HTTP 401 จึงไม่มีสรุปหรือ token usage ที่ตรวจสอบได้ ไม่ส่งไฟล์เสียงและไม่ได้ลองซ้ำ การดาวน์โหลด Qwen3-0.6B Q4 สำหรับทดลองในเครื่องหยุดเพราะความเร็วดาวน์โหลดต่ำ จึงยังไม่มีผล local LLM

Python regression 26 รายการและ Node regression 3 รายการผ่าน; lint ไฟล์ใหม่ผ่าน เริ่ม instance PoC ใหม่แล้วเพื่อโหลด backend ล่าสุด ทดสอบธีมมืดบน Chromium ขนาด 1440 และ 390 พิกเซล และธีมสว่างบน 1440 พิกเซล โดยใช้ public fixture และบล็อกคำขอวัดระดับเสียงจาก browser

## ขั้นต่อไป

1. ขยายชุดเสียงจำลองให้มีหลายสำเนียง ความเร็ว คำศัพท์เฉพาะ ชื่อ ตัวเลข เสียงรบกวน และบทพูดซ้อน พร้อมให้คนฟังตรวจ reference
2. ทดสอบ Whisper รุ่นใหญ่กว่าและ MERaLiON บนข้อมูลเดียวกันเมื่อหน่วยความจำเพียงพอ ประเมิน CER, การตกหล่น, ความถูกต้องของชื่อ ตัวเลข และการสลับภาษา แยกจากเวลาและต้นทุน
3. ติดตั้งโมเดลสรุปและวัดด้วย transcript ที่มีเฉลยเรื่องมติ งาน ผู้รับผิดชอบ กำหนดส่ง และหลักฐาน แยกการประเมินความถูกต้องจาก timestamp
4. หลังได้รับอนุญาตและมีเวลา ให้ตรวจไมค์และ WASAPI loopback ของ Windows กับ Google Meet, Zoom และ LINE จริง แล้วทดสอบสัญญาณขาด การสลับอุปกรณ์ และการพูดซ้อน
5. ตรวจ UX แบบละเอียดต่อในทุกสถานะและทุกเบราว์เซอร์ รวมทั้ง keyboard, contrast, responsive และธีมทั้งแอป
